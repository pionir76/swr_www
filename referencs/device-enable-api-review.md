# 장비 비활성화 기능 — 백엔드 검토 결과 및 조율 사항

> 작성: 2026-10-15
> 상태: **대체됨** (2026-10-16) — 기능을 "지정 장비는 통신하지 않음"으로 단순화하면서 이 문서의 상당 부분이 빠졌습니다. 최종 동작은 `api-changelog.md` 2026-10-16 항목 참고
> 대상 요청서: "장비 비활성화 기능 — 백엔드 API 요청서" (2026-10-15)

---

## 요약

기능 자체는 구현합니다. 다만 요청서의 확정 정책 중 **"폴링 중에도 바로 전환"**은 바꾸자고 제안드립니다.

- **전환은 폴링을 멈춘 상태에서만** 합니다. 다른 장비 설정 변경과 같은 규칙입니다.
- 비활성 장비는 **폴링을 시작할 때 아예 대상에서 뺍니다.**
- 이에 따라 "마지막 값 유지"는 하지 않습니다. 비활성 장비의 값은 **비어 있는 상태(0 또는 null)**가 됩니다.

프론트의 "단독 테스트 / 전체 복귀 / 되돌리기"는 `폴링 중지 → 일괄 전환 → 폴링 시작`을 한 동작으로 묶으면 그대로 만들 수 있습니다.

아래에 이유와 항목별 결과를 정리했습니다. 이 방향에 동의하시면 바로 구현하겠습니다.

---

## 왜 "폴링 중 전환"을 빼는가

상태를 확인하는 비용 자체는 작습니다. 비용이 큰 부분은 **폴링 도중에 상태가 바뀌는 순간**을 처리하는 일입니다.

- 이미 장비로 보낸 요청의 결과를 반영할지, 그 요청이 실패하면 오류를 남길지
- 쌓여 있던 쓰기 요청을 보낼지 버릴지
- 다시 켤 때 실측 주기(`effectiveIntervalMs`) 기준을 어떻게 초기화할지
- TCP 연결을 끊을지, 다시 붙일지
- 진행 중이던 폴링 결과가 `disabled` 상태를 덮어쓰지 않게 막기

모두 스레드 사이의 타이밍 문제라 만들고 검증하는 비용이 큽니다. 반면 쓰임새는 단위 테스트처럼 가끔 켜고 끄는 것이라 얻는 효용이 작습니다.

폴링 시작 시점에 적용하면 비활성 장비에는 폴링 작업 자체가 만들어지지 않으므로, 위 문제가 전부 사라집니다. **같은 버스의 다른 장비 주기가 짧아지는 효과는 그대로 얻습니다.**

**대신 감수할 점**

- 전환할 때마다 **모든 장비의 폴링이 잠깐 끊깁니다.**
- 폴링을 시작하면 전체 값이 초기화되므로, **모든 장비가 첫 응답이 올 때까지 잠깐 `bad`/`unknown`으로 보입니다.** 지금 폴링을 껐다 켤 때와 같은 동작입니다.
- 폴링 중지는 시리얼 장비가 응답 타임아웃을 기다리는 중이면 **몇 초 걸릴 수 있습니다.** 지금 폴링 중지 버튼과 같습니다.

## 항목별 결과

### 3.1 장비 `enabled` 필드 — 요청대로

- `GET /api/devices`의 각 장비에 `"enabled": true|false`를 추가합니다.
- `POST /api/devices`는 생략하면 `true`로 만듭니다.
- `PUT /api/devices/{id}`는 지금처럼 보낸 필드만 바꾸므로, 생략하면 현재 값이 유지됩니다.
- 영구 저장되고 재부팅 후에도 유지됩니다. 기존 장비는 마이그레이션 시 `true`로 채웁니다.
- 백업 `devices.json`에 포함합니다. 예전 백업에 필드가 없으면 `true`로 복원합니다.
- 폴링 중 수정은 지금처럼 **409**입니다.

### 3.2 전환 API — 변경

**단일 장비 전용 API(`PUT /api/devices/{id}/enabled`)는 만들지 않습니다.** `PUT /api/devices/{id}`에 `{ "enabled": false }`만 보내면 됩니다.

**여러 장비 API는 만듭니다.** 단, 폴링 중이면 409입니다.

```
PUT /api/devices/enabled
권한: ManagerOrAbove
```

```json
// 요청
{ "changes": [ { "id": 1, "enabled": true }, { "id": 2, "enabled": false } ] }

// 응답 200
{ "ok": true, "devices": [ { "id": 1, "enabled": true }, { "id": 2, "enabled": false } ] }
```

- 에러 400: 형식 오류
- 에러 404: 없는 장비 id 포함. 이 경우 아무것도 바꾸지 않습니다.
- 에러 409: 폴링 중 `{ "error": "Stop polling before changing devices" }`
- 전부 적용하거나 전부 적용하지 않습니다(트랜잭션).
- 이미 같은 상태인 장비가 섞여 있어도 오류로 보지 않습니다.

**"단독 테스트" 흐름 예시**

1. `POST /api/polling/stop`
2. `PUT /api/devices/enabled` (대상 장비만 `true`, 나머지 `false`)
3. `POST /api/polling/start`

"전체 복귀"와 "되돌리기"도 같은 순서로, 저장해 둔 원래 상태를 2번에 넣으면 됩니다.

### 3.3 장비 상태 — 일부 변경

`GET /api/devices/status`의 각 장비에 `enabled`를 추가하고, 비활성 장비는 `"state": "disabled"`로 응답합니다.

`state`: `"ok"` | `"error"` | `"unknown"` | `"disabled"`

- **`disabledAt` / `disabledBy`는 제공하지 않습니다.** 누가 언제 바꿨는지는 INFO 로그로 남습니다(3.10).
- **`lastPollTimestamp` 유지는 보장하지 않습니다.** 폴링을 시작할 때 모든 장비의 상태를 초기화하므로, 비활성 장비는 `lastPollTimestamp: 0`, `effectiveIntervalMs: 0`이 됩니다.
- 다시 활성화한 장비는 폴링을 시작할 때 `state: "unknown"`, `consecutiveErrors: 0`으로 시작합니다. 요청하신 동작과 같습니다.

### 3.4 대시보드 — 요청대로

- `kpi`에 `disabledDevices`를 추가합니다.
- `errorDevices`, `unknownDevices`에는 비활성 장비를 넣지 않습니다.
- `devices[].state`에 `"disabled"`를 반영합니다.

### 3.5 레지스터 실시간 값 — 변경

**비활성 장비의 레지스터는 `GET /api/registers/realtime` 목록에 나오지 않습니다.** 실시간 목록은 폴링으로 값을 받은 레지스터만 담는데, 비활성 장비는 폴링하지 않기 때문입니다. `quality: "disabled"`는 추가하지 않습니다.

비활성 장비의 레지스터를 화면에 흐리게 보여주려면 장비·레지스터 설정 목록과 `enabled`로 구성해 주세요.

### 3.6 HMI 값 — 일부 변경

- 소스 레지스터의 장비가 비활성이면 **`"q": "disabled"`**로 응답합니다.
- **`v`는 `null`입니다.** 값이 없기 때문입니다.
- `access`는 원래 값 그대로입니다.

`q`: `"good"` | `"normal"` | `"bad"` | `"disabled"`

### 3.7 쓰기 거부 — 요청대로

`POST /api/registers/{registerId}/write`, `POST /api/hmi/write`에서 대상 장비가 비활성이면 아래처럼 응답합니다.

```json
// 409
{ "error": "device disabled", "deviceId": 1 }
```

### 3.8 상위 Modbus 서버 — 질문 1 답변

- **읽기**: 값이 없으므로 `0`을 응답합니다.
- **쓰기**: 정상 응답을 주고 **무시합니다.** 쓰기 큐에도 넣지 않습니다. 예외 응답을 보내려면 요청 처리 단계를 별도로 가로채야 해서 비용 대비 효용이 낮다고 봤습니다.

### 3.9 트렌드 — 변경

비활성 장비 채널은 **`0`으로 기록**됩니다. 기록 형식은 바뀌지 않습니다. 현재 트렌드는 값이 없는 채널을 0으로 기록하는데, 그 동작을 그대로 따릅니다.

### 3.10 로그 — 요청대로

| 시점 | 레벨 | 예시 |
|---|---|---|
| 비활성화 | INFO | `Device disabled: PLC-1 (id=1) by admin` |
| 활성화 | INFO | `Device enabled: PLC-1 (id=1) by admin` |
| 여러 장비 전환 | INFO | 장비마다 한 줄 |

비활성 장비는 폴링하지 않으므로 통신 오류 로그와 알람(`alerts`)이 생기지 않습니다.

## 재부팅

`enabled`는 영구 저장되므로, 비활성인 채로 재부팅하면 그 장비는 계속 폴링하지 않습니다. 값은 처음부터 없습니다. HMI는 `v: null`, 상위 Modbus와 트렌드는 0입니다.
