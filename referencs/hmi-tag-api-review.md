# HMI 태그 API — 백엔드 검토 결과 및 조율 사항

> 작성: 2026-10-14  
> 상태: **조율 중** (구현 전)

---

## 요청서 검토 결과

전반적인 설계 방향은 구현 가능합니다.  
아래 3가지 사항을 확인 후 진행합니다.

---

## 조율 필요 사항

### 1. `quality` 값이 3단계입니다

요청서에는 `"q": "good"` 예시만 있지만, 백엔드 폴링 상태는 3단계로 관리됩니다.

| 값 | 조건 |
|---|---|
| `"good"` | 마지막 폴링 경과시간 < 1.5× interval |
| `"normal"` | 1.5× ~ 3× interval (응답 지연) |
| `"bad"` | 3× 초과 또는 응답 없음 |

→ **프론트에서 `"normal"` 상태도 처리해야 합니다.** 표시 방식(색상 등)을 알려주세요.

---

### 2. `decimals` 필드 — 레지스터 모델에 없음

현재 레지스터에는 `scale` 값만 있고 `decimals`는 없습니다.

두 가지 방식 중 선택이 필요합니다:

**A안 (권장)** — 서버가 `scale`에서 자동 추론해서 내려줌  
`scale=1.0 → 0자리`, `scale=0.1 → 1자리`, `scale=0.01 → 2자리`  
HMI 태그 생성 시 `decimals` 생략하면 자동 계산, 명시하면 오버라이드

**B안** — `decimals` 항상 필수 명시  
프론트에서 레지스터 등록 시 소수점 자리를 직접 관리

→ **A안/B안 중 선호하는 방식 알려주세요.**

---

### 3. `id` 허용 문자 규칙

HMI 태그 `id`는 string으로 DB에 저장됩니다. 유효성 검증 규칙이 필요합니다.

백엔드 제안: **영숫자 + `_` + `-`, 최대 64자**  
예) `TK1_LEVEL`, `PUMP-01-RUN`

→ **이 규칙으로 충분한지, 또는 추가로 필요한 규칙이 있으면 알려주세요.**

---

## 그 외 확인 사항 (요청서 내용 재확인)

- `GET /api/hmi/values` 응답의 `"ts"` 타임스탬프 — ISO 8601 포맷으로 제공 예정 (`2026-10-14T10:30:00`)
- `POST /api/hmi/write`에서 `access: "r"` 태그에 쓰기 시도 시 **405** 반환
- **coil 타입 레지스터** 쓰기: `v == 0.0 → false`, 그 외 → `true` 로 변환 — 이 동작이 맞는지 확인
