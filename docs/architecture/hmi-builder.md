# HMI 빌더 개발 진행 내역

> 최종 갱신: 2026-10-19
> 편집기 4단계(HMI 태그 관리)까지 완료. 5단계(다듬기) 진행 중 — 5-1 ~ 5-5 완료. 위젯별 다듬기·기능 부여 진행 중(라벨 완료, 바운딩 박스 규칙 적용). 남은 것은 "남은 다듬기 후보".

HMI 빌더는 장비 값을 그래픽 화면으로 보여주고 조작하는 페이지(`#hmi`)다. 사용자가 직접 위젯을 배치하고 속성을 편집해 화면을 만들고, 실행 모드에서 실제 값으로 동작시키는 것이 최종 목표다.

### 데이터 저장 (백엔드 API, `referencs/api-spec.md` §14)

- **HMI 태그**: 레지스터 tagName과 별개의 네임스페이스. `/api/hmi/tags`, `/api/hmi/values`, `/api/hmi/write`.
- **화면**: 장비 DB에 **화면 단위**로 저장.
  - `GET/PUT /api/hmi/project` — 이름, 시작 화면, 화면 순서 (프로젝트 revision)
  - `GET/POST/PUT/DELETE /api/hmi/screens/{id}` — 화면 내용 `content`(`format: "whmi.screen"`), 화면별 revision
  - 낙관적 잠금: 저장 시 revision이 다르면 409(저장한 사람·시각 포함)
  - 제한: id `^[A-Za-z0-9_-]{1,64}$`, 제목 64자, content 256KB, 화면 최대 50개
- **백업/복원**: 백업 ZIP의 `hmi.json`에 프로젝트·화면·태그 포함. 태그는 `unifiedAddress`로 레지스터를 다시 찾아 연결. 복원 화면(설정 → 시스템 유지보수)에 "HMI 화면·태그" 항목이 있음(기본 체크, 레지스터 미복원 시 경고).
- **공장 초기화**: HMI 프로젝트·화면·태그 모두 삭제.

### 4단계 세부 — HMI 태그 관리 (모두 장비에서 Playwright 자동 테스트 통과)

디자인 모드 도구줄 [태그 관리] → 대화상자 하나에서 목록 / 폼 / 확인 화면을 바꿔 가며 쓴다. 모달 크기는 고정(목록 영역 60vh, 머리글 표와 목록 표를 나눠 스크롤바는 목록 안에만).

| # | 내용 |
|---|---|
| 4-1 | **태그 목록**: TAG ID · TAG NAME · 소스(장비 · 레지스터) · 단위 · 범위 · 소수점 · 읽기/쓰기 · 현재 값(주황) · 사용처(화면·위젯 수). 레지스터에서 물려받은 값은 흐리게. 검색, 머리글 클릭 정렬(▲▼, 값 없는 행은 항상 뒤, 정렬 상태는 브라우저에 기억) |
| | **점검**: 처음엔 목록만. [점검]을 누르면 데이터를 새로 읽고 단계별로 규칙 적용(단계당 최소 0.35초 표시) → 오류/경고/정보 배지(누르면 그 등급만), 행 앞 ●(마우스를 올리면 이유), [화면 점검] 탭. 규칙은 `TAG_RULES` / `WIDGET_RULES` 목록에 한 줄씩 |
| 4-2 | **하나씩 만들기 / 수정 / 삭제**: 레지스터 설정 화면과 같은 폼(`form-grid`/`form-field`). 소스 레지스터(장비별 그룹), TAG ID(만들 때만, 이후 변경 불가), TAG NAME, 단위·소수점 위치·읽기/쓰기는 선택 상자(첫 항목 "레지스터 상속 (값)"), 최소/최대. 레지스터가 읽기 전용이면 WRITE 선택 불가. 삭제는 사용처 목록과 함께 확인. 버튼은 대화상자 아래 버튼줄(목록: 닫기 / 새 태그: 목록으로·만들기 / 수정: 삭제·목록으로·저장) |
| 4-3 | **여러 개 만들기**(태그 없는 레지스터를 장비별 체크 목록으로, TAG ID·NAME 제안·수정, 진행 표시), **속성 창 "+ 새 태그…"**(새 태그 폼을 바로 열고, 만들면 그 위젯에 연결 후 닫힘 — 실행 취소 가능). TAG ID 제안 = "장비 코드_레지스터 이름"(이미 장비 코드로 시작하면 다시 붙이지 않음) |
| | **여러 개 삭제**: 목록 체크 상자(머리글은 보이는 행만) → [선택 삭제 (N)] → 확인 화면. 기본은 선택한 것 전부 삭제. "화면에서 쓰는 태그"(사용처: 화면별 위젯 id + 용도)와 "쓰지 않는 태그"를 표로 나누고, 행 체크를 풀어 남길 수 있음(구역별 전체 선택/해제) |

- 오류: 소스 레지스터 없음 · 최소 ≥ 최대 · 화면이 정의 없는 태그를 참조(쓰기 허용 조건 포함) · 쓰기 위젯인데 읽기 전용 태그 · 화면 이동 대상 없음/미지정
- 경고: 태그 단위 ≠ 레지스터 단위(연결 실수의 단서) · 현재 값이 범위 밖 · 통신 불량 · 값 위젯에 태그 없음
- 정보: 사용 안 하는 태그 · 같은 레지스터를 쓰는 태그 · 소스 장비 비활성

**동작 원칙**
- 태그 변경은 **바로 서버에 반영**(실행 취소 없음, 삭제만 확인). 저장·삭제 후 편집기 태그 목록·미리보기 갱신 → 자동 점검.
- 태그 API는 폴링 중에도 사용 가능. 일괄 API가 없어 여러 개 만들기/삭제는 하나씩 요청(진행 표시).
- 서버는 태그 단위 ""를 null(상속)로 저장 → 태그에서 단위를 "없음"으로 덮어쓸 수 없음(필요하면 위젯의 "단위 표시"를 끔).

### 사용자 결정 사항

- 화면 저장 단위는 **화면별**.
- 그리는 순서는 자유 — 위젯을 패널(rect) 뒤로 보내는 것도 막지 않음.
- 화면 크기는 장비 해상도가 아니라 **디자인 기준 좌표계**. 실행 시 비율 유지로 확대·축소(여백 가능). 크기를 바꿔도 **위젯 좌표는 유지**(비율 조정 기능 없음).
- 격자 보기와 격자 맞춤은 별도 옵션.
- 위젯은 14종(이미지·상태 표시 추가). 팬 등 다른 추가 위젯은 보류.
- 개발 단계에서는 장비 데이터가 테스트로 바뀌어도 됨 — 무엇이 바뀌었는지만 보고.
- 속성 편집기는 전부 노출(그룹 접기). 여러 위젯 동시 속성 편집은 5단계로 미루고, 같은 종류 위젯 묶음만 지원하는 방향으로 검토.
- 애니메이션은 "사용" 체크로 끄고 켜며, 끄면 ms 칸은 숨기지 않고 비활성. 단위 맞춤 기본값은 하단.
- 장비 비활성(`q: "disabled"`)은 HMI에서 통신 불량과 똑같이 표시(별도 회색 표시 없음).
- 태그 관리는 디자인 모드 안에. TAG ID는 만든 뒤 변경 불가. 정렬에 "문제 순"은 넣지 않음.
- 점검은 버튼으로 실행하고 진행 단계를 보여줌(약간의 연출 — 단계당 0.35초). 저장·삭제 후엔 자동 점검.
- 여러 개 삭제의 기본은 "선택한 것 전부". 확인 화면은 남길 것을 판단하는 가이드.
- 효용 대비 개발비용이 크면 진행 전에 의견을 먼저 제시(단순·확장 가능한 구조 우선).
- 위젯 내용은 바운딩 박스 밖으로 나갈 수 없음. 편집 중엔 상자가 내용에 맞춰 넓어지고, 실행 중 값 길이로 넘치는 것은 디자인으로 해결(자동 축소 없음).
- 기능적으로 좋아도 UI를 복잡하게 만드는 보조 버튼은 넣지 않음(예: 종류가 섞인 선택에서 "○○ N개만 선택" 버튼 제외).

## 3. 남은 다듬기 후보

- **다음 작업(2026-10-21~): 동작 조건 + 가상 태그** — 설계 `docs/architecture/hmi-conditions.md`. 조건 표준 형식 + 위젯 상태 칸 3개(보이기·조작 허용·켜짐), 계산형 가상 태그(백엔드). 아래 "버튼 상태 판정" 보류 항목은 이 설계로 대체.
- 태그 "값 형식"(숫자/비트 워드/값 코드/참거짓 + 비트·값 이름) — 보류(사용자 결정, 지금 규모에선 체감 이득 작음). 검토 결론: 레지스터가 아니라 **HMI 태그에 정의(Y안)** — 레지스터는 통신 설정만, 의미·표시는 HMI(독립 네임스페이스 원칙과 일치). 레지스터의 `bitLabels`는 현재 쓰는 레지스터 없음(40개 중 0) → Y 진행 시 레지스터 폼·실시간 상세의 비트 이름 제거. 단계: ① 백엔드 HMI 태그에 형식·이름 필드(+백업) ② 레지스터 폼 비트 이름 칸 삭제 ③ 태그 관리 폼에 이름 표 편집 ④ HMI 반영(비트 격자 이름, 상태 표시 자동 채우기, 버튼 쓸 값 선택, 점검 규칙). 다시 검토할 시점: 비트 번호를 매번 찾거나 쓸 값을 헷갈리는 일이 반복될 때, 장비·디자이너가 늘 때.
- 버튼 "상태 판정"(켜짐 여부를 다른 태그로 — 명령 레지스터 OPMODE + 상태 레지스터 NOW_STS 같은 구조의 전환 버튼) — 보류(사용자 결정, 추후 고려). 검토한 안: A 위젯별 상태 태그 + 비트(비트를 안 고르면 켜짐 값과 같은지로 판정) / B 사건 기반 HMI 변수(상태가 장비와 어긋날 위험, 비용 큼 — 비권장) / C 다른 태그에서 매번 계산되는 계산 태그(백엔드 협의, 나중에 A의 상태 태그로 고를 수 있음). 지금은 값 쓰기 버튼 두 개 + 상태 표시 위젯으로.
- 긴 단위는 숫자 자리를 줄이고 자동 축소하지 않음, 패널 브라우저 글꼴에 없는 단위 문자(`℃`, `㎥` 등)는 □로 보일 수 있음.
- 화면 이동 모달(screenlink `mode: "modal"`) 미지원 — 팝업 안에서 화면을 하나 더 그리고 폴링해야 해 구조가 커짐. 필요해질 때 진행.
- 권한 세분화(지금은 Manager 이상이면 디자인 모드 전체) — 백엔드 협의 필요.
- 대화상자·편집기 문구 i18n 미적용(한글 하드코딩).

## 5. 테스트 방법

- 장비 배포: paramiko SFTP로 변경 파일만 `/var/www/html/`에 업로드(`deploy.py`는 전체 배포 + 재부팅).
- 자동 테스트: Playwright(playwright-core + chromium)로 실제 장비에 로그인해 실행. 스크립트는 세션 임시 폴더에 두므로 재부팅·세션 종료 시 사라짐(필요하면 다시 작성). 속성 편집기는 `pf1`~`pf4`, 숫자 상자 단위 맞춤은 스크린샷 픽셀로 숫자·단위 글자 획 위치를 측정해 확인, 태그 관리는 `tm1`~`tm12`(테스트 태그는 `ZT_` 접두어로 만들고 끝나면 삭제).
- 저장이 필요한 테스트는 임시 화면(`edtest` 등)을 만들어 진행하고 끝나면 삭제.
