# HMI 할 일 목록

> 최초 2026-11-24. 설계는 **`docs/architecture/hmi.md`**(이 목록의 "§"는 그 문서의 절 번호).
> HMI 작업을 다시 시작할 때는 이 문서부터 읽는다.

## 갱신 규칙

1. 항목을 시작·완료하면 **그 자리에서** 상태를 바꾼다. 완료 항목에는 무엇을 했는지 한두 줄 설명과 날짜를 남긴다.
2. 구현 중 **예외**(설계대로 안 되는 것, 백엔드 답변으로 바뀐 것, 사용자 결정 변경)가 생기면 바로 `hmi.md`의 해당 절을 고치고, 이 문서의 항목과 맨 아래 **변경 기록**에 한 줄을 남긴다.
3. 새 요구는 맞는 단계에 항목으로 넣는다. 어느 단계에도 안 맞으면 "단계 밖 항목"에.
4. 백엔드가 할 일은 요청서(`docs/backend-*.md`)로 보낸다. **보내기 전 사용자 확인 필수.**

상태: ✅ 완료 · 🔄 진행 중 · ⏳ 대기(시작 가능) · 🔒 앞 항목 필요 · ⏸ 보류(필요해질 때)

**백엔드와 합의한 결과**(답변서 `docs/backend-hmi-tag-structure-response.md`, 2026-11-24)

1. 참조 중인 태그 삭제 → **직접 삭제만 409로 거부.** 레지스터·장비 삭제, 복원, 불러오기는 막지 않고, 참조가 끊긴 expr 태그는 남아 `bad`가 됨(`missingRefs`로 표시).
2. 계산 시점 → **값을 요청받을 때 계산**(백엔드에 폴링 묶음 단위가 없음). 한도: 태그 1,000 / 노드 64 / 참조 32 / 깊이 8.
3. 변환 함수 → 백엔드 계산 엔진·쓰기 검사 안에서만 쓰는 순수 함수. 기준은 공통 시험 데이터 `referencs/hmi-testdata-convert.json`.
4. 쓰기 범위 검사 → **서버가 검사, 밖이면 422**(단계 B에 포함).
5. 내보내기 파일 `schemaVersion` → **1 유지.** 예전 펌웨어는 expr·param 태그를 자동으로 건너뛰고 경고. 모르는 kind도 건너뜀. 파일 안 순환 참조는 불러오기 전체 거부.
6. DB → `hmi_tags` 테이블을 새로 만드는 마이그레이션(백엔드, 기존 태그는 자동으로 register). API 형식은 합의서 그대로.
7. 그 밖 → 평가 API는 `POST /api/hmi/eval`(시험 값은 원본으로), param 쓰기는 `{tag, value}`(단계 C에서 확정), 여러 워드는 단계 B와 따로.

## 단계 B — 계산 태그 (expr)

조건 조합(그리고/또는)과 이름 붙은 상태(RUNNING, CAN_START)를 만든다. 예전 "가상 태그 S7".

| | 항목 | 담당 | 설명 |
|---|---|---|---|
| ✅ | B-0 공통 시험 데이터 | 프론트 | `referencs/hmi-testdata-convert.json`(변환 16건), `hmi-testdata-expr.json`(식 36건). 기대 값은 프론트 코드(`WHMI.raw`, `whmi-rules.js`)로 계산(2026-11-24) |
| ✅ | B-1 요청서 | 프론트 | `docs/backend-hmi-expr-tags-request.md` 작성, 사용자 확인 후 전달(2026-11-24). 백엔드 구현 대기 |
| ✅ | B-2 태그 저장 | 백엔드 | DB 마이그레이션, `kind`·`source.valueType`·`source.expr` 저장, 검증(§5.3: 인수·타입·없는 참조·순환·한도), `missingRefs`, 직접 삭제 409, 백업·내보내기 포함 |
| ✅ | B-3 계산 엔진 | 백엔드 | 변환 함수, 연산자 등록부(비교·비트·논리·선택), 값 요청 때 계산, 품질 전파(§5.3, §5.4, §6) |
| ✅ | B-4 값 응답 | 백엔드 | `values`에 expr 태그 `{value, q, unit, access}` |
| ✅ | B-5 평가 API | 백엔드 | `POST /api/hmi/eval`: 식 + 시험 값(원본) → 결과(장비에 쓰지 않음) |
| ✅ | B-5b 쓰기 범위 검사 | 백엔드 | `POST /api/hmi/write`에서 태그 범위 밖이면 422. 프론트는 422 문구 표시 |

| ✅ | B-7 태그 관리 | 프론트 | 새 태그 폼의 종류 고르기(레지스터 / 계산), 값 형식 3종, **조건 빌더**(`js/whmi-expr.js`): 참/거짓은 그리고·또는 묶음(2단까지, 묶음마다 "반대로"), 숫자·글자는 "조건 → 값" 줄 + 그 외 값. 미리보기는 평가 API로 자동(0.5초 뒤), 식 글자·결과·품질·입력 값 표시, "시험 값으로 보기"(register 태그는 표시 값을 원본으로 바꿔 보냄). 빌더로 못 나타내는 식은 글자로만 보이고 그대로 유지. 장치 시험: 만들기·수정 왕복·시험 값·검사 문구·409 안내(2026-11-24) |
| ✅ | B-8 목록·점검 | 프론트 | 목록 소스에 "계산 태그 + 식 글자"(`rules.exprText`), 점검 규칙 "식이 참조하는 태그가 없음"(오류, `missingRefs`)·"입력 태그 통신 불량"(경고), 참조 중인 태그 삭제 시 어느 계산 태그가 쓰는지 안내. 설정 탭 불러오기 미리보기에 끊기는 계산 태그 경고(2026-11-24) |
| ✅ | B-9 회귀·문서 | 프론트 | 쓰기 범위 밖 422를 장치에서 확인하고 실행 화면 상태줄에 "30은(는) 쓸 수 있는 범위(10 ~ 20) 밖입니다"로 표시. 태그 목록의 계산 태그에 입력 태그와 지금 값을 식 아래 한 줄로 표시. 사용처에 "계산 태그 N"(마우스를 올리면 목록), 참조 중인 태그는 삭제 확인에서 미리 막고 이유 안내. 점검의 "안 쓰는 태그"·"같은 레지스터" 규칙을 계산 태그에 맞게 조정(2026-11-24) |

**백엔드 B-2~B-5b 완료·장치 배포(2026-11-24)**, 답변서 `docs/backend-hmi-expr-tags-response.md`. 공통 시험 데이터 52건 서버 통과. 요청서와 달라진 점: PUT에서 `kind` 생략 시 지금 종류 유지 / 평가 API는 없는 태그를 422가 아니라 `bad` + `missingRefs`로 / 불러오기 검증에 `expr`·`brokenExpr` 추가, `linked`는 register 태그만 / `number` 타입인데 숫자로 안 읽히면 `bad` / 계산 태그에 쓰면 405. 장치에 시험 태그 9개(`RUNNING`, `CAN_START`, `STATE_TXT` 등)가 있다.

B-6은 백엔드 응답을 가로챈 가짜 값으로 먼저 만들 수 있다(B-2~B-5와 병행 가능).

## 단계 C — 태그 확장

필요한 것부터 골라 진행한다(서로 독립).

| | 항목 | 담당 | 설명 |
|---|---|---|---|
| ⏳ | C-1 설정 태그(param) | 백엔드 + 프론트 | 사용자가 HMI에서 바꾸는 설정값. 저장·백업·쓰기(`value`), 식에서 참조(예: `TEMP >= 경보기준`). **요청서 보냄(2026-11-25):** `docs/backend-hmi-param-tags-request.md` — 답변 대기. 프론트: 종류 "설정" 폼(값 형식·초기값·단위·최소·최대·자릿수), 쓰기 위젯이 `value`로 쓰기, 1차는 숫자·참/거짓만 |
| ✅ | C-2 산술·집계 연산 (2026-11-25) | 백엔드 + 프론트 | `add sub mul div min max avg abs`. 0으로 나누기는 판정 불가. 숫자 로직 태그의 소수 자릿수 `decimals`(백엔드가 최종 결과 반올림). 폼의 규칙 종류 "계산"(연산 하나 + 값 목록: 태그 또는 숫자)과 "소수 자릿수" 칸. 공통 시험 데이터 71건(산술 35건) 양쪽 통과, 장치에서 저장·값·수정·로직 → 로직 참조 확인. 요청서·답변서 닫음(`docs/backend-hmi-expr-arith-*.md`). **한계(합의):** 지름길 계산이 없어 `select(B≠0, A÷B, 0)` 같은 보호 식은 B=0이면 판정 불가 — 필요해지면 `select`만 고른 가지만 계산하도록 따로 협의 |
| ⏸ | C-3 오프셋 | 백엔드(저장) + 프론트 | register 태그 `offset`. 표시 값 = 원본 × 배율 + 오프셋, 쓰기 역변환·범위 환산·미리보기 |
| ⏸ | C-4 여러 워드 레지스터 | 백엔드 + 프론트 | `values`에 `rawWords`, 실시간 화면의 `RegFmt` 해석 재사용. 쓰기는 별도 검토 |
| ✅ | C-6 빌더 확장 (2026-11-25) | 프론트 | ① **줄에 조건 묶음**: 숫자·글자 태그의 "조건 → 값" 줄에 조건을 여러 개 넣고 그리고/또는으로 묶음(1단, 조건만). 줄의 `+`로 추가. ② **다른 태그와 비교**: 같음·다름·크기 비교 6종의 값 칸 옆 [태그] 단추 → 아래 "비교 태그" 줄에서 장비·태그 선택(`{ op, args: [{tag}, {tag}] }`). 범위·비트 비교는 값 그대로. 백엔드 변경 없음 |
| ⏸ | C-5 태그 값 형식 | 백엔드 + 프론트 | 비트·값에 이름 붙이기(태그에 정의). 비트 격자·상태 표시 자동 채우기·버튼 쓸 값 선택에 사용. 다시 볼 시점: 비트 번호를 매번 찾거나 쓸 값을 헷갈리는 일이 반복될 때 |
