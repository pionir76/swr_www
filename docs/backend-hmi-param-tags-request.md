# HMI 설정 태그(param) — 백엔드 구현 요청서 (단계 C-1)

> 앞선 합의: `docs/backend-hmi-tag-structure-response.md`(구조), `docs/backend-hmi-expr-tags-response.md`(단계 B — `param_init`·`param_value` 열은 이미 있음)

## 1. 요약

**설정 태그**는 사용자가 HMI 화면에서 바꾸는 값을 장치에 저장해 두는 태그입니다. 장비 레지스터와 무관합니다. 예: 경보 기준 온도 80, 허용 편차 2.0, "야간 모드" 켜짐.

로직 태그가 이 값을 참조해 `현재 온도 ≥ 경보 기준` 같은 판정을 합니다(다른 태그와의 비교는 프론트 빌더에 이미 들어갔습니다).

| | 요청 | 비고 |
|---|---|---|
| 1 | `kind: "param"` 태그 저장·검증 | 열은 이미 있음 |
| 2 | `values`에 설정 태그 값 | `{ value, q: "good", unit, access: "rw" }` — 합의된 형식 |
| 3 | 설정 태그 **쓰기** | `POST /api/hmi/write`에 `value` |
| 4 | 로직 태그·평가 API에서 참조 | 값 그대로 |
| 5 | 내보내기·불러오기·백업 | 정의 + 현재 값 — 합의된 내용 |
| 6 | 변경 기록(시스템 로그) | 누가 무엇을 얼마로 바꿨는지 |

---

## 2. 태그 모양

```json
{
  "id": "ALARM_TEMP",
  "name": "경보 기준 온도",
  "kind": "param",
  "source": { "valueType": "number", "initial": 80 },
  "unit": "°C",
  "min": 0,
  "max": 150,
  "decimals": 1
}
```

| 필드 | 규칙 |
|---|---|
| `source.valueType` | `bool` / `number` / `string`. 만든 뒤에도 바꿀 수 있음(아래 4절) |
| `source.initial` | 필수. `valueType`과 같은 타입. 숫자면 `min`~`max` 안 |
| `min` / `max` | 숫자 태그의 쓰기 범위. `null`이면 그쪽 제한 없음. 숫자가 아니면 무시하고 `null` |
| `decimals` | 숫자 태그의 소수 자릿수 0–6 또는 `null`. 로직 태그의 `decimals`와 같은 필드. **쓸 때 이 자릿수로 반올림해 저장** |
| `unit` | 숫자 태그의 단위. 지금 규칙 그대로 |
| `access` | 받지 않음. 응답에서는 항상 `"rw"` |
| `scale` | 쓰지 않음(`null`) |

- 글자 값의 길이는 최대 64자를 제안합니다.
- 검사에 걸리면 422(지금 태그 검사와 같은 모양).
- 전체 태그 수 한도(1,000개)에 함께 셉니다.

---

## 3. 값

- **저장:** 현재 값은 DB에 저장되고 **재부팅 뒤에도 유지**됩니다.
- **만들 때:** 현재 값 = `initial`.
- **`initial`만 고쳤을 때:** 현재 값은 **바뀌지 않습니다**(초기값은 "처음 값"이자 되돌릴 기준일 뿐).
- **`valueType`을 바꿨을 때:** 현재 값을 새 `initial`로 되돌립니다.
- **`min`/`max`를 좁혀 현재 값이 범위 밖이 됐을 때:** 현재 값을 가까운 끝으로 맞춥니다(이견 있으면 알려 주세요. 422로 거부하는 쪽도 괜찮습니다).
- **품질:** 항상 `good`.
- **`values` 응답:** `{ "value": 80, "q": "good", "unit": "°C", "access": "rw" }`
- **`GET /api/hmi/tags` 응답:** 정의와 함께 현재 값을 `value`로 주시면 태그 관리 목록에 쓰겠습니다.

---

## 4. 쓰기

지금의 `POST /api/hmi/write`를 그대로 쓰되, 설정 태그는 `raw` 대신 `value`를 보냅니다.

```json
{ "tag": "ALARM_TEMP", "value": 85.5 }
```

| 경우 | 응답 |
|---|---|
| 성공 | 200 `{ "ok": true, "tag": "ALARM_TEMP", "value": 85.5 }` — 저장된 값(반올림 뒤) |
| 타입이 다름(숫자 태그에 글자 등) | 422 |
| 숫자가 `min`~`max` 밖 | 422 `{ "error": ..., "min": 0, "max": 150, "value": 151 }` — register 태그의 범위 오류와 같은 모양 |
| 글자가 64자 초과 | 422 |
| 설정 태그에 `raw`를 보냄 / register 태그에 `value`를 보냄 | 400 |

- 권한은 지금과 같이 `ManagerOrAbove`입니다.
- 장비에 쓰는 것이 아니므로 바로 반영됩니다. 다음 `values`부터 새 값이 보이고, 이 태그를 참조하는 로직 태그도 새 값으로 계산됩니다.
- "초기값으로 되돌리기"는 프론트가 `initial`을 쓰는 것으로 처리합니다. 별도 API는 필요 없습니다.

---

## 5. 로직 태그·평가 API에서 참조

- 식의 `{ "tag": "ALARM_TEMP" }`는 설정 태그의 현재 값 그대로입니다.
- 참조 중인 설정 태그를 지우려 하면 지금처럼 409 `referencedBy`.
- 순환 참조는 생기지 않습니다(설정 태그는 다른 태그를 참조하지 않음).
- `POST /api/hmi/eval`의 `inputs`에 `{ "ALARM_TEMP": { "value": 90 } }`을 주면 그 값으로 계산합니다(로직 태그 입력과 같은 형식).

---

## 6. 내보내기·불러오기·백업

앞서 합의한 대로입니다. 확인만 부탁드립니다.

- 내보내기와 시스템 백업에 설정 태그의 정의와 **현재 값**이 들어갑니다.
- 불러오기·복원 순서는 register → param → expr.
- 불러올 때 같은 id의 설정 태그가 있으면 파일의 값으로 덮어씁니다(다른 태그와 같은 규칙).

---

## 7. 변경 기록

설정값은 판정 기준을 바꾸는 것이라, 누가 언제 바꿨는지 남아야 합니다. 설정 태그를 쓸 때 시스템 로그에 한 줄을 남겨 주세요.

예: `HMI param ALARM_TEMP: 80 → 85.5 (admin)`

로그 분류와 문구는 백엔드 규칙에 맞추시면 됩니다.

---

## 8. 공통 시험 데이터

`referencs/hmi-testdata-expr.json`에 설정 태그 사례를 프론트가 추가하겠습니다(약 8건).

- `tags`에 `kind: "param"` 태그를 넣고, 사례의 `inputs`에는 `{ "value": 값 }`으로 현재 값을 줍니다.
- 사례: 설정 태그와 비교(`ge(TEMP, ALARM_TEMP)`), 산술에 사용(`sub(ALARM_TEMP, 2)`), 참/거짓 설정 태그를 조건으로, 글자 설정 태그 비교, `inputs`에 없으면 `initial`을 쓰는지.

마지막 항목은 정해야 합니다. **평가 시험에서 `inputs`에 설정 태그 값이 없으면 `initial`로 계산**하는 것으로 제안합니다.

---

## 9. 프론트가 할 일(참고)

- 태그 관리의 종류 "설정"을 켭니다. 폼: 값 형식, 초기값, 단위, 최소·최대, 소수 자릿수.
- 쓰기 위젯(숫자 입력, 버튼, 스위치, 셀렉터)이 설정 태그에는 `value`로 씁니다.
- 1차로는 숫자와 참/거짓만 폼에서 고를 수 있게 합니다. 글자 설정 태그는 화면에서 입력할 위젯이 아직 없습니다(백엔드는 세 타입 모두 받아 주세요).

5. 변경 기록(7절)을 남길 수 있는지
6. 평가에서 `inputs`에 없을 때 `initial`을 쓰는 것(8절)
