## 1. 요약

로직 태그(`kind: "expr"`)의 식에 **숫자 계산 연산자 8개**를 더해 주세요. 지금은 비교·비트·논리·선택만 있어서 "두 온도의 차이", "세 채널의 평균" 같은 값을 만들 수 없습니다.

요청은 두 가지입니다.

| | 요청 | 크기 |
|---|---|---|
| 1 | 연산자 8개 추가: `add` `sub` `mul` `div` `min` `max` `avg` `abs` | 연산자 등록부에 8줄 |
| 2 | 숫자 로직 태그의 **소수 자릿수** 필드 `decimals` 추가(저장 + 결과 반올림) | 필드 1개 |

식 형식(`{tag}` / `{value}` / `{op, args}`), 평가 API, 품질 규칙, 한도는 **그대로**입니다. 새 API는 없습니다.

## 2. 연산자

| 연산자 | 인수 | 결과 | 규칙 |
|---|---|---|---|
| `add` | 2개 이상 | number | 모두 더함 |
| `sub` | 2개 | number | a − b |
| `mul` | 2개 이상 | number | 모두 곱함 |
| `div` | 2개 | number | a ÷ b. **b가 0이면 판정 불가**(`q: "bad"`, `value: null`) |
| `min` `max` | 2개 이상 | number | 가장 작은 / 큰 값 |
| `avg` | 2개 이상 | number | 합 ÷ 개수 |
| `abs` | 1개 | number | 절댓값 |

**공통 규칙**

- **인수 읽기:** 지금의 "숫자로 읽기"와 같습니다(참/거짓은 1/0, 숫자 모양 글자는 숫자). 인수 하나라도 숫자로 읽히지 않으면 결과는 판정 불가(`bad`)입니다.
- **인수 자리:** 태그 참조, 상수, 다른 연산 모두 올 수 있습니다. 예: `sub(max(A, B), min(A, B))`.
- **다른 연산의 인수로:** 산술 결과를 비교·선택의 인수로 쓸 수 있어야 합니다. 예: `gt(sub(PV, SP), 5)`.
- **계산 정밀도:** 배정밀도 실수(double). 결과가 유한한 수가 아니면(넘침 등) 판정 불가입니다.
- **품질:** 지금과 같습니다. 참조한 태그 중 하나라도 `bad`면 `bad`, 지름길 계산 없음.
- **저장할 때 검사(422):** 인수 개수가 위 표와 다르면 거부. 그 밖의 검사와 한도(노드 64, 참조 32, 깊이 8)는 지금 그대로입니다.

**확인 부탁:** `select`의 "값" 자리와 기본값 자리에 지금도 상수 말고 태그 참조나 연산이 올 수 있는지 알려 주세요. 올 수 없다면 이번에 허용해 주시기 바랍니다(예: `select(RUN, sub(PV, SP), 0)`).

## 3. 소수 자릿수 `decimals`

### 왜 필요한가

실수 계산은 `24.72 − 12.45 = 12.269999999999998` 같은 오차가 납니다. register 태그는 배율에서 자릿수가 정해지지만(배율 0.01 → 2자리), 로직 태그에는 기준이 없습니다. 지금 프론트는 "정수가 아니면 2자리"로 임시 처리하고 있어서, 값에 따라 자릿수가 바뀝니다.

### 요청

숫자 로직 태그(`kind: "expr"`, `valueType: "number"`)에 필드 하나를 더해 주세요.

| 필드 | 위치 | 형식 | 뜻 |
|---|---|---|---|
| `decimals` | 태그 최상위(`unit`·`min`·`max`와 같은 줄) | 정수 0–6 또는 `null` | 결과를 이 자릿수로 반올림. `null`이면 반올림하지 않음(지금 동작) |

- **저장:** `POST` / `PUT /api/hmi/tags`에서 받고, `GET /api/hmi/tags`에서 돌려줍니다. 범위를 벗어나면 422.
- **계산:** 식의 **최종 결과**에만 적용합니다(중간 계산은 반올림하지 않음). `values`와 `eval`의 `value`가 반올림된 값입니다. 다른 로직 태그가 이 태그를 참조하면 반올림된 값을 받습니다.
- **반올림 방식:** register 태그의 표시 값과 같은 방식(배율 자릿수 반올림에 쓰는 그 함수)이면 됩니다.
- **적용 대상:** `valueType`이 `number`일 때만 뜻이 있습니다. `bool`·`string` 태그와 register 태그에서는 무시해도 되고 거부해도 됩니다(편한 쪽으로, 알려만 주세요).
- **내보내기·불러오기·백업:** 다른 태그 필드와 같이 따라가야 합니다.
- **평가 API:** `POST /api/hmi/eval` 요청에 `decimals`를 함께 보내면 같은 반올림을 적용해 주세요(저장 전 미리보기용).

## 4. 공통 시험 데이터

`referencs/hmi-testdata-expr.json`에 산술 사례를 프론트가 추가하겠습니다(약 20건). 형식은 지금과 같고, `decimals`가 필요한 사례에는 사례 항목에 `"decimals": 2`를 더합니다.

| 묶음 | 사례 |
|---|---|
| 기본 | 더하기·빼기·곱하기·나누기, 인수 3개 이상의 `add`·`mul` |
| 집계 | `min`·`max`·`avg`, 음수 섞임 |
| 배율 | 배율이 다른 태그끼리(0.1과 0.01), 부호 있는 값 |
| 판정 불가 | 0으로 나눔, 숫자가 아닌 글자, 입력 하나가 `bad` |
| 조합 | 산술을 비교의 인수로, 산술을 `select`의 값으로, 산술 안의 산술 |
| 자릿수 | `decimals` 0·1·2, 반올림 경계(…5), `null` |

요청을 받아들이시면 사례를 먼저 올리고 알려 드리겠습니다. 기대 값에 이견이 있으면 그때 맞추면 됩니다.

## 5. 프론트가 할 일(참고)

- 태그 관리의 숫자 로직 태그 폼에 규칙 종류 "계산"을 더합니다: 연산 하나 + 인수 목록(태그 또는 숫자). 지금의 "조건 → 값"과 나란히 고릅니다.
- 같은 폼에 "소수 자릿수" 칸을 더합니다.
- 조건의 왼쪽에 계산을 직접 넣는 것은 빌더에서 지원하지 않습니다. 계산 태그를 만든 뒤 그 태그를 조건에 씁니다(로직 → 로직 참조).
