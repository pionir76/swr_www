## 1. 범위

합의한 구조 가운데 **계산 태그(`kind: "expr"`)**와 그에 필요한 것만 요청합니다.

| 포함 | 제외(나중 단계) |
|---|---|
| 태그 `kind` 필드, expr 태그 저장·검증 | 설정 태그 `param`(단계 C) |
| 표시 값 변환 함수(백엔드 내부) | 산술·집계 연산(단계 C) |
| 계산 엔진: 비교·비트·논리·선택 | 오프셋, 여러 워드 `rawWords`(단계 C) |
| `values`의 expr 태그 응답 | 시간·상태 연산, 주기 계산(단계 D) |
| 평가 API | |
| 쓰기 범위 검사 | |
| 삭제 규칙, `missingRefs`, 내보내기·백업 포함 | |

`param`은 이번에 구현하지 않지만, DB 마이그레이션에서 컬럼을 함께 만들어 두시는 것은 백엔드 판단에 맡깁니다(답변서 질문 7의 테이블 그대로).

## 2. 요청 사항

### 2.1 태그 API의 `kind`

`GET/POST/PUT /api/hmi/tags`의 태그에 `kind`를 추가합니다.

**expr 태그**

```json
{
  "id": "RUNNING",
  "name": "운전중",
  "kind": "expr",
  "source": {
    "valueType": "bool",
    "expr": { "op": "bitAny", "args": [ { "tag": "NOW_STS" }, { "value": [1, 2] } ] }
  },
  "unit": null,
  "missingRefs": []
}
```

| 필드 | 규칙 |
|---|---|
| `kind` | 요청에 없으면 `register`. 응답에는 항상 포함. **만든 뒤 바꿀 수 없음**(PUT에서 다른 kind면 400) |
| `source.valueType` | `bool` / `number` / `string`. 필수 |
| `source.expr` | AST(2.2). 필수 |
| `unit` | 선택. 숫자 결과에 붙일 단위 |
| `min` / `max` / `scale` / `access` | expr 태그에는 쓰지 않음. 요청에 있어도 무시, 응답 `access`는 `"r"` |
| `missingRefs` | **응답 전용.** 식이 참조하는데 지금 없는 태그 ID 목록. 없으면 `[]` |

register 태그는 지금 형식 그대로이고 `kind: "register"`만 응답에 더해집니다.

**에러**

| 코드 | 경우 |
|---|---|
| 400 | `kind` 값 오류, `kind` 변경 시도, `valueType` 오류, `source.expr` 없음 |
| 422 | 식 검증 실패(2.2) — 본문에 `{ "error": "...", "path": "args[1].args[0]" }`처럼 **문제 노드의 위치**를 주세요. 편집기가 그 줄을 표시합니다 |
| 409 | `DELETE`인데 다른 expr 태그가 참조 중 — `{ "error": "...", "referencedBy": ["CAN_START"] }` |

### 2.2 식(AST)과 연산자

노드는 `{ "tag": "ID" }` / `{ "value": 상수 }` / `{ "op": "이름", "args": [...] }` 세 가지입니다.

| 연산자 | 인수 | 결과 | 규칙 |
|---|---|---|---|
| `eq` `ne` | `[a, b]` | bool | 둘 다 숫자로 읽히면(참/거짓은 1/0, 글자 숫자 포함) 숫자 비교, 아니면 글자 비교 |
| `gt` `ge` `lt` `le` | `[a, b]` | bool | 둘 다 숫자로 읽힐 때만 비교, 아니면 거짓 |
| `range` | `[a, 최소, 최대]` | bool | 최소 ≤ a ≤ 최대(양 끝 포함). 최소·최대가 `null`이면 그쪽은 끝없음 |
| `bitAny` | `[a, 비트 목록]` | bool | a를 정수로 내림해, 목록의 비트 중 하나라도 1 |
| `bitNone` | `[a, 비트 목록]` | bool | 목록의 비트가 모두 0 |
| `and` `or` | `[x, y, …]` (2개 이상) | bool | 인수를 참/거짓으로 읽음 |
| `not` | `[x]` | bool | |
| `select` | `[조건, 값, 조건, 값, …, 기본값]` (홀수 개, 3개 이상) | 값 | 위에서부터 처음 참인 조건의 값, 없으면 기본값 |

- **태그 참조의 값:** register 태그는 표시 값(2.3의 변환 함수), expr 태그는 계산한 값.
- **참/거짓으로 읽기:** 숫자 0, `false`, 빈 글자, 글자 `"0"`·`"false"`는 거짓. 나머지는 참. 그래서 `and`의 인수에 코일 태그를 바로 쓸 수 있습니다.
- **비트 목록:** 0~15의 정수 배열(상수). 비어 있으면 거짓.
- **결과:** `valueType`이 `bool`이면 최종 값을 참/거짓으로 바꿔 내보냅니다.
- **지름길 계산을 하지 않습니다.** `or`의 한쪽이 참이어도 다른 쪽 입력이 `bad`면 결과는 `bad`입니다(품질 규칙을 단순하게 유지).

이 규칙은 프론트 판정 엔진(`js/whmi-rules.js`)과 같습니다. **기준은 공통 시험 데이터**이며, 글과 시험 데이터가 다르면 알려 주세요.

**저장할 때 검증(422)**

- 모르는 연산자, 인수 개수 불일치
- 없는 태그 참조, 자기 자신을 거쳐 돌아오는 순환 참조
- 비트 번호가 0~15 밖이거나 비트 목록이 상수 배열이 아님
- 한도 초과: 전체 태그 1,000개 / 식 하나의 노드 64개 / 식 하나가 참조하는 태그 32개 / expr → expr 깊이 8단

타입 검사는 이번 범위에서 "연산자 인수 개수와 상수 모양"까지만 요청합니다. 태그 값의 타입은 실행 때 정해지므로(숫자로 안 읽히면 비교는 거짓) 저장 때 막지 않습니다.

### 2.3 표시 값 변환 함수 (백엔드 내부)

답변서 질문 3의 정의 그대로입니다.

`원본 → (isSigned면 16비트 2의 보수) → × 배율(태그 scale이 있으면 그것, 없으면 레지스터 scale)`, 코일·접점은 0/1 그대로.

- 결과는 배율의 소수 자릿수로 반올림해 주세요(0.1이면 1자리). `2472 × 0.1 = 247.20000000000002`가 `247.2`와 같다고 판정되어야 합니다.
- 계산 엔진과 쓰기 범위 검사 안에서만 쓰고, 응답에는 싣지 않습니다.
- 확인: `referencs/hmi-testdata-convert.json`(16건).

### 2.4 값 응답

`GET /api/hmi/values`에서 expr 태그는 다음 형식입니다.

```json
{ "RUNNING": { "value": true, "q": "good", "unit": "", "access": "r" } }
```

- 요청받을 때, 요청한 태그와 그 태그가 참조하는 태그만 계산합니다(답변서 질문 2).
- 품질: 참조하는 태그(이어 쓴 expr 태그 포함) 중 하나라도 `bad`/`disabled`이면 `bad`, `normal`이 섞이면 `normal`, 아니면 `good`.
- 다음도 `bad`: 참조한 태그가 없음, register 태그의 원본이 `null`.
- `bad`일 때 `value`는 `null`입니다.
- 확인: `referencs/hmi-testdata-expr.json`(36건).

### 2.5 평가 API `POST /api/hmi/eval`

권한: 로그인한 사용자 누구나. 장비에 쓰지 않고, 저장하지 않습니다.

**요청**

```json
{
  "valueType": "bool",
  "expr": { "op": "and", "args": [ ... ] },
  "inputs": { "NOW_STS": { "raw": 6 }, "RUNNING": { "value": true } }
}
```

- `inputs`는 선택입니다. 준 태그는 그 값으로, 주지 않은 태그는 현재 값으로 계산합니다.
- register 태그는 `raw`(원본)로, expr 태그는 `value`로 줍니다. `q`를 함께 주면 그 품질로, 없으면 `good`으로 봅니다.

**응답 200**

```json
{
  "value": true,
  "q": "good",
  "inputs": {
    "NOW_STS": { "raw": 6, "value": 6, "q": "good" },
    "ALSTS":   { "raw": 0, "value": 0, "q": "good" }
  }
}
```

- `inputs`에는 식이 **직접 또는 이어서 참조한 모든 태그**의 실제 사용 값을 돌려주세요(register 태그는 `raw`와 변환한 `value` 둘 다). 편집기가 "이 값으로 계산했다"를 보여 줍니다.

**에러:** 422(식 검증 실패, 2.1과 같은 `path` 포함). 저장 전 검증에도 이 API를 씁니다.

### 2.6 쓰기 범위 검사

`POST /api/hmi/write`(register 태그)에서:

- 받은 `raw`를 변환 함수로 표시 값으로 바꿔, 태그 `min`/`max`와 비교합니다. 태그 값이 비어 있으면 레지스터 `minValue`/`maxValue`를 **태그 배율로 환산**해 비교합니다(레지스터 범위는 레지스터 배율 기준이므로: `레지스터 값 ÷ 레지스터 배율 × 태그 배율`). "제한 없음"(±1.797e308)은 비교하지 않습니다.
- 범위 밖이면 422 `{ "error": "...", "min": 0, "max": 100, "value": 120 }`.
- 코일·접점은 지금처럼 0/1만 검사합니다.

프론트 입력 창 검사와 같은 규칙입니다(`WHMI.raw.limits`).

### 2.7 삭제·가져오기·백업

답변서 질문 1·6·8 그대로 요청합니다.

- `DELETE /api/hmi/tags/{id}`: expr 태그가 참조 중이면 409 + `referencedBy`.
- 레지스터·장비 삭제, 복원, 가져오기로 register 태그가 사라지는 것은 막지 않습니다. 참조가 끊긴 expr 태그는 남고 값은 `bad`, `missingRefs`에 표시됩니다.
- 내보내기·시스템 백업에 expr 태그 포함. `schemaVersion`은 1 유지.
- 가져오기·복원: register → expr 순으로 넣고, 파일 안에 순환 참조가 있으면 전체 거부. 모르는 `kind`는 건너뛰고 경고.
- 가져오기 검증 응답(`/api/hmi/import/validate`)의 `tags`에 expr 태그 수와, 참조가 끊길 expr 태그 목록을 더해 주세요. 필드 이름은 백엔드가 정해 답변서에 적어 주세요.

## 4. 진행 순서

답변서 4장의 백엔드 순서(DB 마이그레이션 → 변환 함수 → 계산 엔진 → 평가 API → 쓰기 범위 검사)에 동의합니다.

1. **백엔드:** 구현하고, 정해지는 세부(가져오기 검증 응답의 필드 이름 등)를 답변서와 `referencs/api-spec.md`에 적어 주세요. 단계별로 나눠 배포해도 됩니다.
2. **프론트:** 그동안 3장 1~3을 가짜 응답으로 구현합니다.
3. **함께:** 백엔드 배포 후 장치에서 확인합니다.

**기존 동작에 영향 없음:** `kind`가 없는 요청은 지금과 같고, register 태그의 `values`·`write` 형식은 바뀌지 않습니다. 달라지는 것은 범위 밖 쓰기가 422로 거부되는 것 하나입니다.
