# HMI 값을 원본(raw)으로 전환 — 백엔드 답변

> 작성: 2026-11-13 (백엔드)
> 대상: 프론트엔드
> 요청서: `docs/backend-hmi-raw-values-request.md`
> 관련: `referencs/api-spec.md` §14 HMI, `referencs/api-changelog.md` 2026-11-13 (2차)

---

## 1. 요약

요청서 §2를 모두 반영해 장치(192.168.0.150)에 올렸습니다. 전환 순서 §3의 **1단계(백엔드)**가 끝난 상태입니다. `v`/`decimals`(values)와 `v`(write)는 요청대로 남아 있으므로 지금 화면은 그대로 동작합니다.

프론트 전환을 마치고 알려 주시면 3단계(`v`·`decimals`와 서버 역변환 제거)를 진행하겠습니다.

## 2. 반영 내용

| 항목 | 내용 |
|---|---|
| 태그 `scale` | 신규. `null` = 레지스터 상속. 허용 값 `100`·`10`·`1`·`0.1`·`0.01`·`0.001`, 그 밖은 400 `'scale' must be null or one of ...`. 저장만 하고 계산하지 않습니다 |
| 태그 `decimals` | 폐지. 요청에 와도 무시, 응답에 없음 |
| 태그 `source` | 응답 전용 필드 추가: `registerType`, `length`, `scale`, `isSigned`, `minValue`, `maxValue`. 레지스터를 찾지 못하면 `null` |
| `values` `raw` | 원본 워드(uint16). coil·discrete_input은 0/1 |
| `write` `raw` | 원본 워드 그대로 기록. 정수 0–65535(coil은 0/1) 밖이면 400 |
| 기존 태그 | `scale`은 `null`(상속). 장치의 `TEMI2KMF_NPV` 태그도 상속으로 바뀌었습니다(예전 `decimals: 2`는 버림) |
| 백업 | `hmi.json` 태그에 `scale`(상속이면 생략). `decimals`는 넣지 않음 |
| 이전 백업 복원 | `decimals` 무시, `scale`은 상속 |

## 3. 요청서 §5 질문에 대한 답

1. **여러 워드 레지스터:** 레지스터 화면에서 1–4워드를 고를 수 있고 수집도 되지만, 현재 장치의 레지스터는 모두 1워드입니다. 이번에는 **1워드만 지원**합니다.
   - 2워드 이상 레지스터에 연결된 태그는 `values`의 `raw`가 `null`이고, 쓰기는 **422**(`HMI write supports single-word registers only ...`)입니다. 지금까지는 첫 워드만 조용히 써졌습니다.
   - 판단에 쓰시도록 태그 `source.length`를 내려 드립니다. 태그 대화상자에서 2워드 이상 레지스터는 고르지 못하게 하거나 경고해 주세요.
   - 실제로 필요해지면 그때 `rawWords` 배열을 추가하겠습니다.
2. **쓰기 범위 검사:** 서버는 원래 `/api/hmi/write`에서 태그 `min`/`max` 검사를 하지 않았습니다. 없앨 것은 없고, 범위 검사는 프론트 입력 창에서 해 주세요. (참고: 예전 `v` 쓰기는 음수를 0으로 잘라서 썼습니다. `raw`로 바꾸면 이 문제도 사라집니다.)
3. **`unit`/`access` 상속:** 지금처럼 서버가 합니다. 배율에서 끌어내는 값은 더 만들지 않습니다.

## 4. 전환할 때 알아 두실 점

- **`raw`가 `null`인 경우:** `q`가 `bad`·`disabled`일 때, 아직 값을 받지 못했을 때, 2워드 이상 레지스터일 때입니다. 요청서대로 `bad`·`disabled`는 `null`로 했습니다. 지금 `v`는 이때도 마지막 값을 내려 주지만(명세와 달랐음), 화면이 이미 `q`로 거르고 있고 곧 없어질 필드라 고치지 않았습니다.
- **`raw`는 잘리지 않습니다:** 지금 `v`는 레지스터 `minValue`/`maxValue` 범위로 잘린 값입니다. `raw`는 장비 값 그대로라, 범위 밖 값이면 `v`와 다르게 보일 수 있습니다.
- **레지스터 `minValue`/`maxValue` 기본값:** 설정하지 않은 레지스터는 `±1.7976931348623157e308`(double 최댓값)이 내려옵니다. 태그 `min`/`max` 상속을 환산할 때 이 값은 "제한 없음"으로 처리해 주세요.
- **`decimals`(전환 기간):** 이제 태그 `scale`(없으면 레지스터 `scale`) 기준 자릿수입니다. 태그에 따로 넣었던 자릿수는 쓰지 않습니다.
- **`v`(전환 기간):** 여전히 **레지스터** 배율 값입니다. 태그 `scale`은 반영하지 않습니다.
- **쓰기 응답:** 202는 "쓰기 요청을 받았다"는 뜻입니다. 장비가 거부해도 응답은 202이고 장치 로그에만 남습니다. 지금과 같습니다.

## 5. 장치에서 확인한 것

| 확인 | 결과 |
|---|---|
| 기존 DB 이전 | `hmi_tags`에 `scale` 칸 추가, 기존 태그는 `scale: null` |
| 태그 생성 `scale: 0.5` | 400 |
| 태그 생성 `scale: 0.01` + `decimals: 3` | `scale: 0.01` 저장, `decimals` 무시 |
| 태그 수정 `scale: null` / `100` | 저장·응답 정상 |
| `values` | `raw`(예: 2474), `v` 247.4, `decimals` 1 |
| 쓰기 `raw` 현재값 | 202, 장비 1(보조룸 온도제어기) 기록 정상 |
| 쓰기 `raw` −1 / 65536 / 1.5 / `"5"` / 없음 | 400 |
| coil 쓰기 `raw` 2 / 현재값 | 400 / 202 |
| 읽기 전용 태그 쓰기 | 405 |

시험용 태그는 지웠습니다.

참고: 장비 3(메인챔버 온습도조절기, `TEMI2KMF`)은 쓰기에 Modbus 예외 1(지원하지 않는 기능)로 응답합니다. 레지스터 쓰기 API에서도 같으므로 이번 변경과 관계없는 장비 쪽 설정 문제입니다.
