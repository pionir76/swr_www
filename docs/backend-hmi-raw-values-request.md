# HMI 값을 원본(raw)으로 전환 — 백엔드 API 요청서

> 작성: 2026-11-13 (프론트엔드)
> 대상: SmartRoute 백엔드(swr)
> 관련 명세: `referencs/api-spec.md` §5 레지스터, §14 HMI
> 관련 원칙: `docs/architecture/overview.md` §5 "원본 데이터 원칙"

---

## 1. 배경과 목적

### 1.1 원칙

SmartRoute는 처음부터 다음 원칙을 전제로 합니다.

> **백엔드는 원본(raw) 데이터만 다룹니다. 배율(소수점) 적용과 역변환은 프론트엔드가 합니다.**
> 시스템의 모든 배율 설정은 **원본값 기준**이며 서로 독립입니다.

예: 원본값이 `1234`일 때

| 보는 곳 | 배율 설정 | 결과 |
|---|---|---|
| 레지스터·대시보드·트렌드 | 레지스터 `scale` 0.1 | 1234 × 0.1 = **123.4** |
| HMI 태그 | 태그 배율 0.01 | 1234 × 0.01 = **12.34** (레지스터 설정과 무관) |
| HMI 태그 | 비움(상속) | 레지스터 0.1을 물려받아 **123.4** |
| 상위 Modbus 서버 | — | **1234** (원본 그대로, 지금과 같음) |

### 1.2 현재 어긋난 곳

트렌드(`/api/tfile/sample`, 원본 uint16)와 Modbus 서버는 이 원칙대로 동작합니다. HMI만 서버가 계산합니다.

| API | 현재 | 문제 |
|---|---|---|
| `GET /api/hmi/values` | 서버가 배율을 적용한 `v`만 내려 줌 | HMI 태그에서 원본 기준 배율을 줄 수 없음 |
| `POST /api/hmi/write` | 서버가 `raw = round(v / scale)`로 역변환 | 배율 계산이 서버와 프론트 두 곳에 있음 |
| HmiTag `decimals` | "표시 자릿수" 뜻으로 저장 | 레지스터의 배율과 이름은 비슷한데 뜻이 달라 사용자가 헷갈림 |

이번 요청으로 HMI도 **서버는 저장과 원본 전달만**, **계산은 프론트**로 맞춥니다.

---

## 2. 요청 사항

### 2.1 HmiTag 모델: `decimals` → `scale`

```json
{
  "id": "TK1_LEVEL",
  "name": "1번 탱크 수위",
  "source": { "registerId": 123, "...": "..." },
  "unit": "%",
  "min": 0.0,
  "max": 100.0,
  "scale": 0.01,
  "access": "r"
}
```

| 항목 | 요청 |
|---|---|
| `scale` | 새 필드. `null`이면 레지스터 `scale`을 상속합니다. 허용 값은 레지스터와 같은 `100`, `10`, `1`, `0.1`, `0.01`, `0.001`이고, 그 밖의 값은 400 |
| 서버 역할 | **저장하고 돌려주기만** 합니다. 서버 안에서 이 값으로 계산하지 않습니다 |
| `decimals` | 폐지합니다. 요청 바디에 들어와도 무시하고, 응답에서 뺍니다. 표시 자릿수는 프론트가 배율에서 정합니다(0.01이면 2자리) |
| `min`/`max` | 지금처럼 저장만 합니다. 단위는 **태그 배율을 적용한 값**입니다. `null`일 때 레지스터 값을 환산해 물려받는 일도 프론트가 합니다 |
| `unit`/`access` | 지금과 같습니다 |

### 2.2 HmiTag `source`에 레지스터 정보 추가 (응답 전용)

프론트가 원본을 해석하는 데 필요합니다. 기존 `source` 필드와 같은 규칙으로, 저장하지 않고 응답할 때 레지스터에서 채워 주세요. 레지스터를 찾을 수 없으면 `null`입니다.

| 필드 | 출처 | 쓰는 곳 |
|---|---|---|
| `registerType` | 레지스터 `type` | coil·discrete_input은 0/1 불리언으로 해석 |
| `scale` | 레지스터 `scale` | 태그 `scale`이 `null`일 때 상속 |
| `isSigned` | 레지스터 `isSigned` | 원본 uint16을 부호 있는 값으로 해석 |
| `minValue`/`maxValue` | 레지스터 `minValue`/`maxValue` | 태그 `min`/`max`가 `null`일 때 배율을 환산해 상속 |

### 2.3 `GET /api/hmi/values`: `raw` 추가

```json
{
  "ts": "2026-11-13T02:26:05Z",
  "values": {
    "TK1_LEVEL": { "raw": 1234, "q": "good", "unit": "%", "access": "r" }
  }
}
```

| 항목 | 요청 |
|---|---|
| `raw` | 장비에서 읽은 **원본 워드 그대로**(uint16, 0–65535). 부호 해석·배율 적용 없이 `registers/realtime`의 `rawWord`와 같은 값입니다. coil·discrete_input은 `0`/`1` |
| 값이 없을 때 | 지금 `v`와 같은 규칙으로 `bad`·`disabled`이거나 아직 값이 없으면 `null` |
| `q`/`unit`/`access` | 지금과 같습니다 |
| `v`/`decimals` | **전환 기간에는 그대로 둡니다**(§3). 프론트 전환이 끝나면 뺍니다 |

### 2.4 `POST /api/hmi/write`: 원본값으로 쓰기

```json
{ "tag": "LEVEL_SP", "raw": 7500 }
```

| 항목 | 요청 |
|---|---|
| `raw` | 장비에 쓸 **원본 워드**(uint16, 0–65535). 서버는 배율 계산 없이 그대로 씁니다. 음수는 프론트가 2의 보수로 바꿔 보냅니다(`-5` → `65531`). `POST /api/registers/{id}/write`의 `rawValues`와 같은 규칙입니다 |
| coil | `raw`는 `0`/`1` |
| 범위 밖 | 정수가 아니거나 0–65535 밖이면 400 |
| `v` | 전환 기간에는 받아 줍니다. `raw`와 `v`가 함께 오면 `raw`를 씁니다. 전환이 끝나면 `v`와 서버 쪽 역변환을 없앱니다 |
| 나머지 | 404·405·409 오류는 지금과 같습니다 |

### 2.5 기존 데이터와 백업·복원

| 항목 | 요청 |
|---|---|
| 기존 태그 | `decimals` 값은 버리고 `scale`은 `null`(상속)로 둡니다. 현재 HMI 데이터는 새로 만드는 중이라 변환은 필요 없습니다 |
| 백업 | `hmi.json` 태그에 `scale`을 넣고 `decimals`는 뺍니다 |
| 이전 백업 복원 | `decimals`는 무시하고 `scale`은 `null`로 복원합니다 |

---

## 3. 전환 순서

화면이 중간에 깨지지 않게 다음 순서로 진행합니다.

1. **백엔드:** §2를 반영합니다. `values`의 `v`/`decimals`와 `write`의 `v`는 **남겨 둡니다**.
2. **프론트:** 계산을 프론트로 옮깁니다. 값 = 원본(부호 해석) × 배율, 쓰기 = round(입력 ÷ 배율)을 uint16으로 변환. 태그 대화상자의 "소수점 위치"는 레지스터와 같은 배율 선택(상속 / 100 … 0.001)과 미리보기(`원본 1234 → 12.34`)로 바꿉니다.
3. **확인 후 백엔드:** `values`에서 `v`/`decimals`를 빼고, `write`의 `v`와 역변환을 없앱니다. 프론트가 완료를 알려 드립니다.

---

## 4. 이번 범위가 아닌 것

- `GET /api/registers/realtime`의 `scaledValue`: `rawWord`가 함께 오므로 지금은 그대로 둡니다. 프론트가 `rawWord`로 옮긴 뒤 따로 정리합니다.
- Modbus 서버: 이미 원본을 내보내므로 변경 없습니다.
- 트렌드: 이미 원본(uint16)이므로 변경 없습니다.

---

## 5. 확인 부탁드릴 점

1. **여러 워드 레지스터:** 레지스터에 `length`가 있습니다. `length`가 2 이상(32비트 정수·실수)인 레지스터가 실제로 쓰이나요? 쓰인다면 `raw`를 워드 배열(`rawWords: [w0, w1]`)로 주실지, 서버가 `byteOrder`대로 합친 정수로 주실지 정해야 합니다. 지금처럼 모두 1워드라면 이번에는 1워드만 다루겠습니다.
2. **쓰기 범위 검사:** 서버가 지금 `/api/hmi/write`에서 태그 `min`/`max`로 범위를 검사하고 있다면, 그 검사는 배율이 필요하므로 없애 주세요. 범위 검사는 프론트 입력 창에서 합니다.
3. **`values`의 상속 처리:** `unit`/`access`의 상속 해석은 계산이 아니므로 지금처럼 서버가 해도 됩니다. 다만 `decimals`처럼 배율에서 끌어내는 값은 더 만들지 말아 주세요.
