## 2. 연산자 — 이견 없음, 한계 하나

2절 표와 공통 규칙대로 구현합니다.

- 인수 개수: `add`·`mul`·`min`·`max`·`avg`는 2개 이상, `sub`·`div`는 2개, `abs`는 1개. 다르면 저장할 때 422(`path` 포함)입니다. 지금의 다른 연산자와 같습니다.
- 인수는 지금의 "숫자로 읽기"로 읽습니다. 하나라도 숫자가 아니면 판정 불가입니다. 상수 `{ "value": null }`도 숫자가 아니므로 판정 불가입니다.
- 결과가 유한한 수가 아니면(0으로 나눔, 넘침) 판정 불가입니다.
- 한도(노드 64, 참조 32, 깊이 8)는 그대로입니다.

### 한계: 고르지 않은 가지도 결과를 망칩니다

단계 B 규칙에는 **지름길 계산이 없습니다.** 모든 인수를 계산하고, 하나라도 판정 불가면 결과도 판정 불가입니다. 산술이 들어오면 이 규칙 때문에 다음과 같이 됩니다.

```
select( ne(B, 0), div(A, B), 0 )      B = 0이면 → 0이 아니라 판정 불가
```

`div(A, B)` 가지를 고르지 않아도 그 가지가 판정 불가라서 전체가 판정 불가가 됩니다. 계산을 별도 로직 태그로 만들어 참조해도 결과는 같습니다. 그래서 "0이면 나누지 않기" 같은 보호 식은 만들 수 없습니다.

- 이번에는 **이대로 갑니다.** 요청서의 규칙("지름길 계산 없음")과 같고, 백엔드와 `js/whmi-rules.js`가 같은 결과를 내야 하기 때문입니다.
- 이것이 실제로 필요해지면, 다음 단계에서 **`select`만** 고른 가지만 계산하도록 바꾸는 안을 따로 협의하겠습니다. 양쪽 규칙과 공통 시험 데이터를 함께 바꿔야 합니다.
- 화면 안내문 등에 "참조한 태그나 계산 중 하나라도 판정 불가면 결과도 판정 불가"라고 적어 두시면 좋겠습니다.

---

## 3. `select` 값 자리 — 지금도 됩니다

`select`의 모든 인수(조건·값·기본값)는 일반 노드로 검사하고 계산합니다. 상수, 태그 참조, 연산이 모두 올 수 있습니다. 따라서 연산자만 추가되면 `select(RUN, sub(PV, SP), 0)`은 바로 동작합니다. 바꿀 것은 없습니다.

산술을 비교의 인수로 쓰는 것(`gt(sub(PV, SP), 5)`)과 산술 안의 산술도 마찬가지로 됩니다.

---

## 4. `decimals`

이름 `decimals`, 태그 최상위(`unit`·`min`·`max`와 같은 줄), 정수 0–6 또는 `null`. 요청서 그대로입니다.

| 항목 | 동작 |
|---|---|
| 저장 | `POST`·`PUT /api/hmi/tags`에서 받고 `GET`에서 돌려줍니다. 정수가 아니거나 0–6 밖이면 **422** |
| PUT에서 뺐을 때 | HMI 태그 PUT은 지금처럼 **전체 교체**입니다(`unit`과 같음). `decimals`를 빼면 `null`(반올림 안 함)이 됩니다. 수정할 때도 항상 보내 주세요 |
| 숫자가 아닌 태그 | `bool`·`string` 로직 태그와 register 태그는 **무시하고 `null`로 저장·응답**합니다. 거부하지 않는 이유: 값 형식을 `number`에서 바꿀 때 남은 `decimals` 때문에 PUT이 막히지 않게 하려는 것입니다 |
| 계산 | 식의 **최종 결과에만** 적용합니다. `values`·`eval`의 `value`가 반올림된 값이고, 이 태그를 참조하는 다른 로직 태그도 반올림된 값을 받습니다 |
| 반올림 | register 태그 배율 자릿수에 쓰는 함수와 같습니다. `-0`은 `0`으로 돌려줍니다 |
| `eval` | 요청 바디 최상위에 `"decimals": 2`를 주면 같은 반올림을 합니다. 범위 밖이면 422입니다 |
| 내보내기·불러오기·백업 | 로직 태그에 `decimals`가 같이 따라갑니다. 불러오기에서 범위 밖이면 다른 식 오류처럼 400입니다. `decimals`가 없는 예전 파일은 `null`로 읽습니다 |

DB는 `hmi_tags`에 열 하나만 더합니다. 지금 태그는 모두 `null`이 되어 동작이 바뀌지 않습니다.

반올림 경계(`…5`)는 실수 표현 때문에 기대와 다를 수 있습니다(예: 1.005는 실제로 1.00499…라서 1.00). 공통 시험 데이터의 경계 사례로 양쪽이 같은 값을 내는지 PC 시험에서 확인하겠습니다.

## 7. 구현 결과 (2026-11-25, 장치 192.168.0.150에 배포)

답변서 2–4절대로 구현했습니다. API 형식은 명세 §14와 변경 이력 2026-11-25에 적었습니다.

**공통 시험 데이터:** `hmi-testdata-expr.json` 71건(산술 35건 포함)과 변환 16건이 서버 PC 시험에서 모두 통과합니다.
- 반올림 경계도 기대 값과 같습니다(12.5 → 13, 0.125 → 0.13, 1.005 → 1, −0 → 0). 서버 반올림 함수(Qt `QString::number(x, 'f', n)`)는 printf와 달리 JavaScript `toFixed`처럼 정확한 절반을 0에서 먼 쪽으로 보냅니다.
- 태그 `DIFF`의 최상위 `decimals`와 사례의 `decimals`를 모두 읽습니다.

**장치 시험(35건 통과):**

| 항목 | 결과 |
|---|---|
| 태그 저장 | `decimals` 0–6·`null` 저장과 응답. 7, −1, 1.5, `"2"`는 422(`path` 없음). `bool` 태그에 보낸 `decimals`는 범위와 상관없이 무시하고 `null` |
| PUT | `decimals`를 빼면 `null`, 0으로 바꾸기, 8은 422 |
| 인수 개수 | `sub` 3개 → 422 `path: ""`, 안쪽 `abs` 0개 → 422 `path: "args[0]"` |
| values | `sub(HUMI_NPV, TEMP_NPV)`에 `decimals: 1` → 75.3. 이 태그 + 0.04 → 75.34(반올림된 값을 받음). `avg` 3개에 2자리 → 45.73 |
| eval | 0으로 나눔 `bad`, 0.125 → 0.13, 12.5 → 13, −0.01(1자리) → 0, 자릿수 없으면 `12.269999999999998` 그대로, 숫자 아닌 글자 `bad`, `true × "2.5"` → 2.5, `max − min`을 비교에 넣기, 보호 식 `select(ne(B,0), div(A,B), 0)`(B = 0) → `bad` |
| 내보내기·불러오기 | `decimals`가 있는 태그만 키가 있음. 불러오기 검증에서 9는 400. 내보낸 파일을 다시 적용하면 `decimals` 유지 |
| 재시작 | 값 유지, 경고 없음 |

- DB: `hmi_tags`에 `decimals` 열을 더했습니다. 프론트가 만든 태그 30개는 그대로이고 모두 `decimals: null`입니다.
- 시험 태그(`T_` 다섯 개)는 지웠습니다. 시험 중 HMI 내보내기 파일을 한 번 다시 적용했으므로 태그와 화면의 `createdAt`·`updatedAt`이 바뀌었을 수 있습니다. 내용은 같습니다.
- 장치 DB 백업은 `/var/lib/swr/smartroute.db.bak-before-arith`에 있습니다.

프론트에서 확인해 보시고 문제가 없으면 요청서와 답변서를 닫아 주세요.
