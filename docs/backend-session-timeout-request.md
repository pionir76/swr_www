# 세션 타임아웃(서버 만료) — 백엔드 API 요청서

> 작성: 2026-11-11 (프론트엔드)
> 대상: SmartRoute 백엔드(swr)
> 관련: `docs/policy/user-management.md` §10·§12·§21-6, `referencs/api-spec.md` §1 인증·보안 정책
> 상태: **반영 완료(2026-11-11)** — 백엔드 `referencs/api-changelog.md` 2026-11-11, 웹은 비밀번호 변경 401 예외 제거. 장치 시험 통과(5절 항목 + 비활성화·비밀번호 초기화 시 즉시 로그아웃)

---

## 1. 배경

보안 정책의 `sessionTimeoutMinutes`(장치 현재값 10분)는 저장·조회·백업만 되고, **실제로 세션을 끝내지 않습니다.**

- 2026-11-11 장치 확인: 정책을 1분으로 두고 250초 동안 쓰지 않은 토큰으로 `GET /api/session`을 보내면 200이었습니다.
- 소스 확인: 세션은 `m_sessionUsers`(토큰 → 사용자명)뿐이고 마지막 사용 시각이 없습니다(`api/ApiServer.h:174`).
- 그 결과 한 번 발급된 토큰은 **장치를 재시작할 때까지 계속 유효**합니다. 브라우저를 닫거나 PC를 꺼도 마찬가지이고, 토큰이 새면 계속 쓸 수 있습니다.

이번 요청은 정책을 두 단계로 나눈 것 중 **1단계(서버 만료)**입니다.

| 단계 | 담당 | 내용 |
|---|---|---|
| **1. 서버 만료 (이번 요청)** | 백엔드 | 일정 시간 **요청이 없는** 토큰을 무효화 — 브라우저를 닫은 세션 정리 |
| 1. 만료 시 로그인 화면 이동 | 프론트 | 완료(아래 4절) |
| 2. 무조작 자동 로그아웃 | 프론트 | 나중에. 웹 화면은 열려 있는 동안 1~3초마다 자동으로 요청을 보내므로, "사람이 조작하지 않음"은 서버가 알 수 없고 웹이 키보드·마우스 입력으로 판단해야 합니다 |

## 2. 요청 사항

### 2.1 세션 만료

| 항목 | 요청 |
|---|---|
| 마지막 사용 시각 | 토큰마다 마지막 요청 시각을 기록하고, 인증이 필요한 요청(`requireAuth` 통과)마다 갱신해 주세요 |
| 만료 판단 | `지금 - 마지막 요청 시각 > sessionTimeoutMinutes`이면 그 토큰은 무효입니다. 요청이 들어올 때 판단하면 충분하고, 오래된 세션 정리는 타이머(예: 1분 주기)로 해도 됩니다 |
| 만료된 토큰 응답 | 지금 "세션에 토큰 없음"과 같게 **401**로 주세요. `GET /api/session`도 401이면 됩니다(웹은 이미 이렇게 처리) |
| 정책 변경 반영 | `PUT /api/users/security-policy`로 시간을 바꾸면 **기존 세션에도 바로** 적용해 주세요(만료 판단 때 현재 설정값 사용) |
| `autoLogout`과의 관계 | 서버 만료는 `autoLogout`과 **상관없이 항상** 적용해 주세요. `autoLogout`은 2단계(웹의 무조작 로그아웃) 켜기·끄기용으로 남겨 둡니다. 화면을 켜 둔 관제 패널은 계속 요청을 보내므로 서버 만료로 끊기지 않습니다 |
| 로그 | 만료로 세션을 지울 때 `INFO Session expired: <username>` 정도면 충분합니다(선택) |

### 2.2 비밀번호 변경: 현재 비밀번호 틀림 → 400

`PUT /api/users/{username}/password`는 현재 비밀번호가 틀리면 **401**(`Current password is incorrect`)을 돌려줍니다(`api/ApiServer.cpp:1712`).

웹은 401을 "세션 만료"로 보고 로그인 화면으로 보내므로, 이 응답은 **400**으로 바꿔 주세요(본문은 그대로). 지금은 웹이 이 경로만 예외로 두고 있고, 바뀌면 예외를 지우겠습니다.

## 3. 확인 부탁드릴 점

1. 사용자를 **비활성화**(`PUT /api/users/{username}/status`)하거나 **잠금**하면, 그 사용자가 이미 받은 토큰은 바로 무효가 되나요? 아니라면 1단계와 함께 무효화해 주시면 좋겠습니다(삭제는 `requireAuth`의 DB 조회 실패로 이미 401).
2. 비밀번호를 바꾸면 그 사용자의 다른 세션을 끝낼지 의견 부탁드립니다(선택).

## 4. 프론트엔드 반영 내용 (완료, 장치 배포됨)

- `apiFetch`(`config.js`) 한 곳에서, 토큰을 보냈는데 **401**을 받으면 저장된 토큰을 지우고 `login.html?expired=1`로 이동합니다. 로그인 화면에 "세션이 만료되었습니다. 다시 로그인하세요."를 표시합니다(4개 언어).
- 제외: `/api/login`, `/api/logout`, `/api/session`(페이지 시작 때 따로 판단). 비밀번호 변경 예외는 2.2 반영 후 제거.
- 403(권한 부족)은 로그아웃하지 않습니다.
- 시험: 다른 곳에서 토큰을 무효화(`/api/logout`)하면 대시보드·실시간·트렌드 화면 모두 약 1.3초 안에 로그인 화면으로 이동했습니다.

## 5. 반영 후 확인 방법

```text
1. PUT /api/users/security-policy { "sessionTimeoutMinutes": 1 }
2. 토큰 A, B 발급. A는 그대로 두고, B는 20초마다 GET /api/session
3. 약 70초 뒤: A → 401, B → 200
4. 웹: 로그인한 채 브라우저 탭을 닫고 70초 뒤 다시 열면 로그인 화면
5. 정책을 원래 값으로 되돌림
```
